# order: 175
# title: UI: book, player & downloads
# subtitle: Book detail, the Downloaded tab, the mini-player and player sheet, and listening reporting
This page is the second half of the `UI` module. The first half ([[UI/RootView.swift]] and friends) is the app shell and the browsing tabs; this half is everything that happens once the listener picks a [[term:Book]]: its detail screen, downloading it, playing it, and telling the [[term:Server]] what was listened to.

`UI` sits at the top of the module graph ([[#module-graph]]): it may import `Domain`, `Store`, `Sync`, `Downloads` and `Playback`, and nothing imports it. The files here lean on three objects from lower modules: the `AppDatabase` (from `Store`), the one `Player` (from `Playback`) and the `Downloader` (from `Downloads`). The app target builds those once and hands them in ([[#composition-root]]).

The pattern is the same on every screen. A **model** class (`BookDetailModel`, `DownloadsModel`) is marked `@Observable`, reads its first values synchronously from the database in `init` so the very first frame has real content, and then follows the database with an `observe()` method that a view runs in `.task`. A **view** `struct` reads the model and calls its methods. Background work (`Downloader`, `LibrarySync`) never calls the UI back; it writes to the database, and the models notice ([[#single-source-of-truth]]).

The `Player` is the exception: it is `@Observable` itself and the player views read it directly (its position changes several times a second, too often to go through the database). It is put into the SwiftUI environment once by [[UI/PlayerChrome.swift]], and so is the shared `DownloadsModel`, so any view deep in the tree can pick them up with `@Environment`.

!ios **SwiftUI in one paragraph.** A screen is a `struct` conforming to `View` with a `body` property that *describes* the UI. You never mutate on-screen widgets; you change state, and SwiftUI calls `body` again and diffs the result. `VStack`/`HStack` stack children vertically/horizontally, `List` is a scrolling table, and chained calls like `.font(.headline)` are **modifiers** that wrap a view in another view. See [[#primer-swiftui]].

!rule ADR 0001: the database is the single source of truth. A model never gets pushed state by Sync or Downloads; it observes the Store. If you add a screen, copy the shape of `BookDetailModel`: read in `init`, follow in `observe()`.

=== LogosKit/Sources/UI/BookDetailModel.swift
The model behind Book detail. It owns a `BookDetail` value (title, author, Series, Chapters, description, size) read from the Store, plus the small amount of formatting the screen needs. It also contains the HTML-to-plain-text conversion for the Server's descriptions.
--- 1-14
!ios `import` brings in other modules. `Domain` holds the value types (`BookDetail`, `Chapter`), `Store` the database, `Sync` the `LibrarySync` this model asks for missing data. `Observation` is Apple's framework that provides `@Observable`.

!ios `@Observable` (a macro, see [[#primer-observable]]) rewrites the class so that SwiftUI records which properties a view's `body` read, and redraws only that view when one of them changes. You write ordinary `var`s; no publishers or bindings needed. It only works on classes, which is why models are `final class` while views are `struct`s.

`final` means no subclasses; `public` because the type is used from the app target and tests, which are other modules.
--- 15-22
A nested value type for one Series link: the id to navigate with and the label to show ("Fixture Saga #1.5").

!ios `struct` is a value type (copied on assignment, like a number), `class` a reference type (shared). The protocols after the colon are capabilities: `Sendable` = safe to pass between threads, `Hashable` = usable in sets and as navigation values, `Identifiable` = has an `id`, which `ForEach` and `List` use to tell rows apart. `var id: String { seriesID }` is a *computed property*: no storage, worked out on every read.
--- 23-33
The state. `public private(set)` means anyone can read `detail` but only this class can write it. `progress` is a separate small model ([[UI/InProgressModel.swift]]) for "not started / 2 h left / Finished", shared with the In Progress tab.
--- 34-46
The initializer reads the Book from the database synchronously. That is deliberate: the screen should open with real content in its first frame (the "Tap Book → detail" budget is 100 ms, see [[#performance]]).

!ios Swift error handling: a function marked `throws` must be called with `try`, inside `do { } catch { }` (or propagated). In `catch`, an implicit `error` constant holds what was thrown. Here a failed read is logged and the screen shows "Book not found".

`log` is this module's logger ([[UI/Log.swift]]). The `privacy: .public` part is from Apple's unified logging: interpolated values are redacted in logs by default, so code opts in per value.
--- 47-74
Derived values for the view, all computed properties so they're always in step with `detail`.

!ios `detail?.series ?? []` is *optional chaining* plus the *nil-coalescing* operator: if `detail` is `nil` the whole expression is `nil`, and `??` substitutes an empty array. `guard let detail else { return "" }` unwraps an optional or leaves early; after it, `detail` is non-optional. `series.sequence.map { ... }` on an optional runs the closure only if there is a value.

A Book always has at least one [[term:Chapter]] once stored: no Chapters from the Server means one Chapter covering the whole Book (see [[Domain/Chapter.swift]]).
--- 75-85
Follows the Book in the database for as long as the screen is visible.

!ios `async` functions can suspend (wait) without blocking the thread; you call them with `await`. `for try await x in sequence` loops over an *async sequence*: each iteration waits for the next value. Here the sequence is a GRDB `ValueObservation` wrapped by the Store ([[Store/BookDataStore.swift]]), which emits a new `BookDetail` every time the relevant rows change. The loop ends when the task running it is cancelled (when the view goes away), see [[#primer-concurrency]].
--- 86-93
Early in the first sync a Book may only have its list row, not its full data (Chapters, description). Rather than show a half-empty screen until the background sync reaches it, the detail asks `LibrarySync` to fetch this one Book now ([[Sync/LibrarySync+BookData.swift]]). The result arrives through the database, so `observe()` picks it up; this method only toggles the spinner. A [[term:Not on Server]] Book is skipped: the Server no longer has it.

!ios `defer { ... }` runs when the scope exits, however it exits. It guarantees `isFetching` goes back to `false`.
--- 94-109
Two formatters reused across the player screens: whole durations ("2 h 5 min") and clock times ("4:05", "1:02:05"). `static` means they belong to the type, not an instance: `BookDetailModel.clock(...)`.
--- 110-116
!ios An `extension` adds methods to an existing type, even one declared elsewhere. The project uses them a lot to split a type across files by topic (`BookDetailModel+Finished.swift`, `Player+SleepTimer.swift`). Here `LibraryModel` ([[UI/LibraryModel.swift]]) gets a factory, so every list that opens a detail builds it the same way with the same database and sync.
--- 117-133
The Server's description is HTML. Converting it with `NSAttributedString` would pull in WebKit and must run on the main thread, which would hurt the detail's open time, so the code does a small regex pass instead: line and block breaks become newlines, other tags go, entities are decoded, whitespace tidied.

!ios `#"...<br\s*/?>..."#` is a *raw string*: backslashes are literal, handy for regular expressions. `private` at file level means only this file can see the function.
--- 134-
A hand-written HTML entity decoder: named ones (`&amp;`, `&nbsp;`…) plus numeric `&#233;` and `&#xE9;`. Anything it can't decode is left as a literal `&`.

!ios `Substring` is a view into part of a `String` without copying it. String indices in Swift are opaque (`String.Index`), not integers, because characters can be several bytes long; hence `firstIndex(of:)` and `index(after:)` rather than `i + 1`.

!ios `ForEach(Array(model.chapters.enumerated()), id: \.element.id)` loops over (index, chapter) pairs. `\.element.id` is a *key path*, a reference to a property that SwiftUI uses as each row's identity. `Section { } header: { }` is a trailing-closure syntax with labels for the extra closures.

=== LogosKit/Sources/UI/PlayActions.swift
What the primary button of a downloaded Book says and does: Play, Resume or Pause.
--- 1-24
!ios A Swift `enum` lists a fixed set of cases, and can carry computed properties. `switch` must handle every case (the compiler checks), and in Swift 5.9+ a single-expression `switch` can be used directly as a property's value, as in `title` here. --- 25-46

=== LogosKit/Sources/UI/ListeningReporter.swift
Decides *when* to send the [[term:Outbox]] ([[term:Listening session]]s and [[term:Finished change]]s) to the Server. The *what* and *how* live in `SessionOutbox` ([[Sync/SessionOutbox.swift]]). Created for a signed-in identity in [[UI/LaunchModel.swift:139]] and run by the shell.
--- 1-25
The first seam: is any network usable? The real implementation wraps `NWPathMonitor` from Apple's `Network` framework in an `AsyncStream`.

!ios `protocol` declares a set of requirements a type can conform to, like an interface. `AsyncStream` turns callback-based APIs into an async sequence: the closure gets a `continuation`, you `yield` values from the callback, and `onTermination` cleans up when the consumer stops listening. `.bufferingNewest(1)` keeps only the latest status if nobody is reading.
--- 26-53
The second seam: a short **background task**. When the app goes to the background iOS suspends it within seconds; `beginBackgroundTask` asks for a little more time so a send can finish. If time runs out the task just ends, and the send is retried at the next trigger. See [[#primer-background]].

!ios `UIApplication` is UIKit, the older UI framework underneath SwiftUI; some system services are still only reachable through it. The private `Running` class holds the task identifier so both the expiry handler and the returned closure can end it exactly once.
--- 54-79
!why Sends are fire-and-forget: playback never waits for the network. A failed send costs nothing because the outbox is in the database and is retried on the next trigger. The defaults (`SystemConnectivityMonitor()`, `SystemBackgroundTasks()`) mean production code passes nothing, and tests pass fakes ([[#seams]]).
--- 80-93
`run()` is the whole schedule: send once now (launch), every 60 s while playing, whenever a Finished change is recorded, when playing stops, and when the network comes back.

!ios `withDiscardingTaskGroup` is a task group whose children return nothing; it runs them all concurrently until cancelled. The `stops` stream is subscribed *before* the group starts so no stop is missed in between.

=== LogosKit/Sources/UI/SleepTimerMenu.swift
The [[term:Sleep Timer]] menu in the player sheet. The timer counts [[term:Chapter]]s, not minutes: "stop at the end of the 3rd Chapter from now, counting this one". The logic is `SleepTimer` in [[Domain/SleepTimer.swift]] and `Player+SleepTimer` ([[Playback/Player+SleepTimer.swift]]); this file only words and presents it.
--- 1-19
How an option reads: "End of this Chapter" or "3 Chapters", with a projected stop in wall-clock time at the current speed ("Stops at end of Chapter 7 · ~42 min").
--- 20-53
!ios `Menu { } label: { }` is a button that opens a pop-up menu of buttons; nested `Menu`s become submenus. `Section(text)` inside a menu adds a titled group.

Unset, the menu lists the options. Set, it shows the projected stop, "+1 Chapter" (only if there is a next Chapter), Cancel, and Change.

=== LogosKit/Sources/UI/SpeedControl.swift
The speed button and picker. Speed is global (one setting for all Books), from 0.5× to 3.0× in 0.05 steps, applied immediately. The constants live in `PlaybackSpeed` ([[Domain/PlaybackSettings.swift]]).
--- 1-24
The button shows the current speed ("1.5×") and opens a short sheet (`.presentationDetents([.height(300)])`).
--- 25-
The picker: preset buttons, a slider with − and + buttons for fine steps. Each change calls `player.setSpeed`, which also saves it.

!why Speed changes sound natural thanks to the player's time-domain pitch algorithm (`AVAudioTimePitchAlgorithm.timeDomain`, Apple's speech algorithm, set in [[Playback/SystemAudioPlayer.swift:57]]); this view doesn't need to know about that.
