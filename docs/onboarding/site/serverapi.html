ServerAPI

every byte Logos exchanges with the audiobookshelf Server

ServerAPI is the module that talks HTTP to the Server. It knows audiobookshelf's URLs, headers and JSON shapes, turns them into the plain values Domain defines (ListedBook, BookData, FetchedProgress, …), and turns every failure into one small error type. Nothing else in Logos builds a URLRequest or reads a Server response.

In the The module graph it sits directly on top of Domain and depends on nothing else. Sync and Downloads use it; Playback is forbidden from importing it, which is how the codebase guarantees playback never reaches the network. The app target (LogosApp.swift) creates the real implementations once and hands them down.

The module has three parts:

  • The request/response seam. The ServerAPI protocol (ServerAPI.swift) lists every call. AudiobookshelfClient is the real implementation over URLSession; FakeServer is a scripted, in-memory audiobookshelf used by the unit tests and by test launches. The Requests and Responses namespaces build requests and decode responses, split per topic over several files.
  • Authentication. Auth (an actor) owns the access/refresh token pair, refreshes it ahead of time or after a 401, and turns a rejected refresh into "Needs sign-in". TokenPair reads token lifetimes; TokenStore keeps the pair in the Keychain.
  • Background file transfers. The FileTransfers protocol is the seam for downloading audio files with a background URLSession, which keeps going while Logos is suspended or not running. BackgroundFileTransfers is the real one, FakeFileTransfers the scripted one.
Why it is like this

The protocol methods are stateless: each takes the Server URL and an access token as arguments. Only Auth holds tokens, and callers wrap their call in auth.authorized { token in … }, so no caller ever handles a 401 or a refresh itself (see the comment at the top of ServerAPI.swift).

House rule

Never point anything at a real Server from tests. Unit tests use FakeServer; the integration tests run against a throwaway audiobookshelf in Docker (see Integration tests (against a real Server)). HTTPS is not enforced here, so the Docker Server's plain HTTP works; the HTTPS-only rule lives in sign-in, in Sync.
