Welcome to Logos

An onboarding guide to the code: what the app does, how it is built, and why it is built that way.

What Logos is

Logos is a personal iPhone app for listening to audiobooks from an audiobookshelf server. audiobookshelf is open-source software you run yourself (at home or on a small cloud machine). It holds your audiobook files and remembers how far you have got in each one. Logos is a client for it: it signs in to the server, shows its book list, downloads whole books to the phone, and plays them.

A few product decisions shape almost all of the code, so keep them in mind as you read:

  • It plays only from downloads. Logos never streams audio over the network. A Book must be fully downloaded and checked before it can be played. That is why the playback code (the Playback module) is not even allowed to talk to the network.
  • One server, one library, one user. At sign-in you choose a single Library and the app works with that. There is no account switching.
  • Nothing is lost if the app is killed. Everything the screen shows is already saved on disk, in a local SQLite database. Listening progress made offline is kept in an Outbox and sent to the server later.
  • It must be fast on a big library. There are written performance budgets (for example, a cold launch with 3000 books must show the library in under 400 ms). See Performance budgets.
  • iOS 27, iPhone only, Swift 6. The code uses the newest language and frameworks without compatibility layers for older iOS versions.

How to read this guide

The guide has three parts. Read the first two from start to finish. Use the third as a reference.

  1. Background. The iOS & Swift primer explains the platform ideas the code depends on (SwiftUI, @Observable, async/await, actors, Swift packages, background downloads, AVFoundation, GRDB). If you have built an iOS app before, skim it.
  2. The big picture. Architecture explains the modules, the rules between them, where state lives, and follows the main user journeys (sign in, sync, download, play, sign out) through the code. Working in the repo covers setup, checks, tests, pull requests and the house rules.
  3. Annotated source. One page per module. Each page shows every source file with notes in the left column next to the code. The code is read straight from the repository each time the guide is built, so it is always the current code. Blue boxes explain an iOS or Swift idea the first time it shows up. Orange boxes explain why something is done the way it is. Red boxes are house rules.

Words matter here

The project keeps a strict shared vocabulary in GLOSSARY.md, shown in this guide as the Glossary. A capitalised word in a comment or doc, like Book, Download, Finished or Series, means exactly what the glossary says. The code avoids synonyms: it says "Book", never "item" or "title", even though the audiobookshelf API calls them "library items". When you see a capitalised term in the notes, it links to its definition.
