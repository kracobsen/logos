# PROTOTYPE — multi-file playback: composition timeline vs queue player

Throwaway. Answers [Prototype: multi-file playback — composition timeline vs queue player](https://github.com/kracobsen/logos/issues/12).

```sh
Prototypes/MultiFilePlayback/run.sh            # Simulator; generates the test Books on first run
Prototypes/MultiFilePlayback/run.sh --regenerate
```

On a device: open `MultiFilePlaybackPrototype.xcodeproj`, set a team, Run. The lock screen and Control Center
checks only mean anything there.

Scripted pass, log to stdout: `xcrun simctl launch --console-pty <device> no.kracobsen.logos.prototype.multifile -autorun clock-oddsplits -engine Queue`.

## Test Books

The "talking clock" Books are generated by `tools/make-test-books.swift`: 15 minutes, a voice in the **left ear** says
the Book time every 10 s, and a continuous tone plays in the **right ear**.

| Book | Files |
|---|---|
| Clock · single file (.m4b) | 1 |
| Clock · one file per Chapter (AAC) | 6, split on the Chapter boundaries |
| Clock · odd splits (AAC) | 5, split off the Chapter boundaries: a 7 s file, and one split in the middle of a word |
| Clock · odd splits (MP3) | the same splits as MP3; only generated if `lame` is installed (`brew install lame`) |

Real Books: **Server…** signs in (the password is not stored), lists the Library with a "Multi-file Books only"
filter, and downloads a Book's files plus its Chapters.

## What to check, per engine (switch in the player; the position is kept)

- **Gaps at file boundaries**: use headphones, tap *Next boundary ▶︎*, and listen for a dropout or click in the
  right-ear tone. The log's ⚠︎ lines are the gap detector, which only sees gaps inside the decoded audio.
- **Seek accuracy**: use *Go to* (e.g. `6:40`) or tap a Chapter. The voice should say that time. *Run seek test*
  logs the landing error and latency at 1×, 1.5× and 2×.
- **Chapter mapping**: for real Books, the load log shows each file's actual duration against the Server's
  duration, and the drift that builds up (Composition only).
- **Start latency**: the log's *ready to play after* and *play → playing* lines.
- **Now Playing**: on the lock screen, check the title, Chapter n/N, progress, ±15/30 s skip, scrubbing and speed,
  with *Lock screen shows Chapter progress* both on and off.
